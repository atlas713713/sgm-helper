# 武当 75 级精英副本（精英濮阳之战）执行步骤

本文是从武当 APK 反编译结果里逐段扒出来的 75 级**精英**副本流程，作为地球助手复刻的对照
基准。一般副本的共用流程见 [武当副本执行步骤.md](武当副本执行步骤.md)，本文只在必要时重复，
重点放在**精英和一般的差异**上。

来源类：`Dungeon75Action`、`BaseDungeonAction`、`DungeonUtil`、`GotoDungeonPalaceAction`、
`NPCDialog`、`Console`，以及 `res/values/arrays.xml` 的 `dungeon_pro_list`。

坐标有两套，不要混：

- **地图坐标**：走位用，副本内地图宽度 `typeX = 199`，宫殿地图 `typeX = 399`。
- **屏幕坐标**：点 NPC、点对话行用，基准 `1280 × 720`。

---

## 一、配置数据

`arrays.xml` → `dungeon_pro_list`：

```json
{"showName":"75精英","name":"精英濮阳之战","id":2075,"level":75,"type":2,
 "camp":"精英濮阳城内","enterNpc":"吕布","exitNpc":"陈宫"}
```

对照一般副本（`dungeon_list`）：

```json
{"showName":"75一般","name":"濮阳之战","id":1075,"level":75,"type":1,
 "camp":"濮阳城外","enterNpc":"吕布","exitNpc":"陈宫"}
```

`Dungeon75Action` 构造函数里写死、一般和精英**共用**的量：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `mapType` | `199` | 副本内地图宽度 |
| `direction` | `1` | 推进方向：向右 |
| `enterNpcLocation` | `(100, 16)` | 宫殿里进副本 NPC 的地图坐标（`DungeonUtil.m`，75 走默认值） |
| `exitLocation` | `(187, 27)` | 副本内出口坐标 |
| `part0Gate` | `(73, 27)` | 第一段的门 |
| `part1Flag` | `(130, 27)` | 第二段的旗 |
| `centerLocation` | `(120, 25)` | 地图中心 |
| `part0BeginX` / `part0EndX` | `0` / `78` | 第一段 x 区间（`part0BeginX` 声明了但没赋值，默认 0） |
| `part1BeginX` / `part1EndX` | `79` / `199` | 第二段 x 区间 |
| `priorityEnemyNames` | 吕虔、于禁、李典、夏侯渊 | 优先攻击的 BOSS，按此顺序 |
| `npcButtonNext` / `npcButtonEnter` / `npcButtonEnter2` / `npcButtonBack` | 下一步 / 出发 / 进入 / 离开 | 进副本对话按钮 |
| `exitBtnNext` / `exitBtn` | 下一步 / 收下战利品 | 出副本对话按钮 |

两个由 `dungeonEntity` 拼出来、精英和一般**不同**的 OCR 串：

| 字段 | 一般 | 精英 |
| --- | --- | --- |
| `enterExitOcr` = `name + camp` | `濮阳之战濮阳城外` | `精英濮阳之战精英濮阳城内` |
| `ocr` = `camp + name + "副本宫殿(一般)副本宫殿(精英)"` | `濮阳城外濮阳之战副本宫殿(一般)副本宫殿(精英)` | `精英濮阳城内精英濮阳之战副本宫殿(一般)副本宫殿(精英)` |

## 二、精英 vs 一般：只有三处不同

整条路线、BOSS 优先级、出口坐标、对话按钮全都一样。**入场三步不同**，进副本之后完全共用
`Dungeon75Action` 的代码：

| 差异点 | 一般（type 1） | 精英（type 2） | 出处 |
| --- | --- | --- | --- |
| 驻地引路员对话选第几行 | 第 1 行 `(251, 450)` | **第 2 行 `(251, 512)`** | `GotoDungeonPalaceAction.talkNpc` |
| 要等待的宫殿地图名 | `副本宫殿(一般)` | **`副本宫殿(精英)`** | `GotoDungeonPalaceAction.checkMap` |
| 宫殿内副本入口坐标 | `(152, 16)` | **`(73, 20)`** | `DungeonUtil.h`，`typeX = 399` |

第三点值得单独说：精英宫殿是**另一张地图**，入口 x 从头重新编号（60 精英在 26、65 在 41、
70 在 57、75 在 73、80 在 89），而且 y 是 `20` 不是 `16`。拿一般副本那张表去精英宫殿走位
会直接走错地方。

驻地名也不同（`濮阳城外` → `精英濮阳城内`），它只影响 OCR 校验，不影响走位。

## 三、步骤机总览

`Dungeon75Action.dispatch` 每轮先跑一次前置检查（`E0`），再按 `step` 分派：

| step | 方法 | 名字 | 干什么 |
| ---: | --- | --- | --- |
| 0 | `o0` | `check` | 判断人在哪：城里 / 宫殿 / 副本内 |
| 1 | `v0` | `gotoEnterNPC` | 在宫殿里走到进副本 NPC |
| 2 | `G0` | `talkEnterNPC` | 和吕布对话进副本 |
| 3 | `r0` | `checkTalkEnterNPC` | 确认真的进去了 |
| 4 | `s0` | `doDungeon` | 副本内推进（本文第五节） |
| 5 | `w0` | `gotoExitLocation` | 走到出口 `(187, 27)` |
| 6 | `t0` | `exitDungeon` | 和陈宫对话领奖离开 |
| 7 | `q0` | `checkExit` | 确认已经出来 |
| 8 | `p0` | `checkError` | 异常兜底 |
| 9 | `B0` | `noCount` | 没有副本次数 |
| 10 | `u0` | — | 收尾小步骤 |
| 其它 | `F0` | — | 结束整个 action |

`step = 999` 表示这次副本跑完。

## 四、入场：从城里到副本内

### 步骤 1：回城并确认主城

回城，等主城地图加载完成，OCR 地图名拿到当前城市。

### 步骤 2：走到驻地引路员

地图坐标（`typeX = 399`）：

- 洛阳 / 成都 / 建业：`(200, 31)`
- 其他主城：`(210, 33)`

### 步骤 3：和驻地引路员对话，选「精英」

1. 到位后点 NPC 快捷键 `(1208, 410)`。
2. 只 OCR NPC 名字标题区域，确认标题是「驻地引路员」。
3. **点第 2 行 `(251, 512)`** —— 一般副本点第 1 行 `(251, 450)`，试炼点第 3 行 `(251, 574)`。

对话行的屏幕坐标来自 `NPCDialog`（我们这一档布局：x = 133，宽 236 → 中心 251；四行 y 分别
430 / 492 / 554 / 616，高 40 → 中心 450 / 512 / 574 / 636）。

### 步骤 4：等宫殿地图

每秒 OCR 一次地图名，等到 **`副本宫殿(精英)`**，最多 30 次。

### 步骤 5：走到副本入口

宫殿地图坐标 **`(73, 20)`**（`typeX = 399`）。

### 步骤 6：走到进副本 NPC 并对话（step 1 → 2）

1. 进入副本地图后走到 `enterNpcLocation = (100, 16)`（`typeX = 199`）。
2. 点 NPC 快捷键 `(1208, 410)`。
3. OCR NPC 名字，确认是 **吕布**。
4. 按按钮文字点选项：`下一步` → `出发` / `进入`（找不到就用 `离开` 退出重来）。

> 我们的实现走的是固定行号 `entryNpcRows = {4, 3, 3}`，不是按文字找。这是一处**实现差异**，
> 见第七节。

### 步骤 7：确认进入（step 3）

OCR 地图名，出现驻地名 `精英濮阳城内` 才算进去了；否则回到 step 1 重试。

---

## 五、副本内推进（step 4）

副本内地图 `typeX = 199`，方向向右。`doDungeon` 每轮读一次自己的坐标，按 x 落在哪一段决定
调用 `part0` 还是 `part1`：

```
x ∈ [0, 78]   → part0(currentLocation)
x ∈ [79, 199] → part1(currentLocation, part1BeginX, part1EndX)
```

### part0：推到门口

目标是 `part0Gate = (73, 27)`。沿途用 `toRight` 一格格向右推：读当前坐标 → 算下一个点 →
`gotoLocation` 过去 → 遇敌就打。优先打 `priorityEnemyNames`（吕虔 → 于禁 → 李典 → 夏侯渊），
没有优先目标就打普通敌人。

x 过了 78 就进 part1。

### part1：推到旗，再推到出口

目标依次是 `part1Flag = (130, 27)` 和 `exitLocation = (187, 27)`。同样是 `toRight` 推进 +
优先打 BOSS。`part1` 里维护一个 `noBossCount`：连续几轮找不到 BOSS 就认为这一段清完了，继续
向右。

`centerLocation = (120, 25)` 用于需要回中间重新找目标的情况。

### 全程并行的检查（`BaseDungeonAction`）

这些不在 step 机里，是每轮都跑的：

- `checkDead` —— 角色死亡（日志 `====角色已死亡====`）
- `checkVerCode` —— 反外挂验证码
- `fullInventory` / `needResizeInventory` / `resizeInventory` —— 背包满
- `safetyOption` —— 安全设置
- `checkLeaveDungeonDialog` —— 误触离开副本的确认框
- `updateCaptainLocation` —— 组队时跟队长

---

## 六、离开（step 5 → 7）

1. **step 5**：走到 `exitLocation = (187, 27)`。
2. **step 6**：点 NPC 快捷键 `(1208, 410)`，OCR 确认是 **陈宫**，按文字点 `下一步` →
   `收下战利品`。
3. **step 7**：OCR 地图名确认已经离开副本；成功则 `step = 999` 收工。

## 八、我们的实现对应关系

| 武当 | 地球助手 |
| --- | --- |
| `Dungeon75Action`（entity type 1） | [Dungeon75Action.java](../app/src/main/java/com/local/sgmhelper/Dungeon75Action.java) |
| `Dungeon75Action`（entity type 2） | [Dungeon75EliteAction.java](../app/src/main/java/com/local/sgmhelper/Dungeon75EliteAction.java) |
| `BaseDungeonAction` + `DungeonUtil` | [BaseDungeonAction.java](../app/src/main/java/com/local/sgmhelper/BaseDungeonAction.java) |
| `dispatch` 步骤机 | [DungeonBattleAutomation.java](../app/src/main/java/com/local/sgmhelper/DungeonBattleAutomation.java) |

武当用一个类加 `dungeonEntity` 区分一般和精英，我们拆成了父子类：`Dungeon75EliteAction`
只覆盖那三处差异（`dungeonType` = 2、`dungeonName` = `精英濮阳之战|濮阳之战`、
`campName` = `精英濮阳城内`、`campNpcX/Y` = `(73, 20)`），路线和 BOSS 顺序直接继承。

### 已知实现差异

1. **进副本 / 出副本的对话选项**：武当按按钮文字找行（`出发` / `进入` / `收下战利品`），
   我们用固定行号（`entryNpcRows = {4, 3, 3}`、`exitNpcRows = {4, 4, 4}`）。行号是实测出来
   的，但游戏加减一个选项就会错位，按文字找更稳。
2. **路线分段阈值**：武当是 `part0 = [0, 78]`、`part1 = [79, 199]`；我们的 `decideRoute`
   多了一个 `x < 65` 的分支（65 以下先搜怪再去门口）。这个 65 不在武当的配置里，是我们自己
   加的，来源存疑。
3. **`part0BeginX`**：武当声明了这个字段但从没赋值，实际是 0。如果以后发现有副本靠它做左
   边界，要重新确认。

### 尚未复刻

- `updateCaptainLocation`（组队跟队长）——我们只跑单人。
- `resizeInventory`（副本内背包整理）——我们是记下事件、出副本后再回城处理。
